Architecture & Mission

In causal language model pre-training, subtle bugs in loss computation—such as misaligned label shifts, incorrect padding token weighting, cross-document contamination, and naive autograd graph retention—often manifest not as obvious exceptions, but as degraded downstream performance or artificially low, meaningless loss curves.

This repository establishes a Correct and Observable Loss Harness with zero tolerance for silent errors. Built from scratch with PyTorch and verified against Karpathy's TinyShakespeare corpus and GPT-2 tokenization, each component is sealed by exact mathematical and programmatic assertions.

Key Guarantee: Targets originate from a single source of truth (make_targets). No ad-hoc label shifting is permitted across training or evaluation loops, and all token indices are decoded into explicit string representations with whitespace/newline visibility.

Item 1 — Tensor Shapes and Memory Semantics

Traced across a test batch of $B=4, T=32, D=256, V=50258$. Each rank and dimension represents a concrete semantic concept in causal modeling.

Hidden Memory Cost of Naive Slicing: Slicing logits[:, :-1] renders the tensor non-contiguous in memory. Calling .reshape(-1, V) forces PyTorch to perform an eager memory copy. At $B=8, T=1024, V=50258$ (fp32), this eagerly copies 1.645 GB of memory into temporary buffers before computing loss! Slicing hidden first eliminates this copy completely.

Item 2 — Target Shift Verification & Negative Controls

A language model must predict the future token $t+1$ given tokens up to $t$. We verify this alignment with explicit string decodings and execute negative control experiments.

Negative Controls: The "Beautiful, Meaningless Curve" Warning

When an engineer accidentally aligns targets to $t$ (identity) or $t-1$ (retrieval), the model can simply extract the answer already embedded in its prefix activations. The loss collapses to near-zero immediately, fooling unobservant practitioners.

Item 4 — Document Packing and Boundary Masking

Concatenating multiple documents into one sequence eliminates padding waste. However, the transition token where input is $A_{\text{last}}$ (or EOT) and target is $B_0$ represents an unlearnable prediction across disjoint contexts.

The Packing Identity: The relation $\text{loss}_{\text{before}} \times n = \text{loss}_{\text{after}} \times (n-1) + \text{boundary\_nll}$ holds with tolerance $< 10^{-5}$. Removing the boundary token reduces mean loss by $(\text{boundary\_nll} - \text{loss}_{\text{after}}) / n$, purifying training signal from random document transition penalties.

Item 7 — Peak Memory: Ordinary vs Chunked Cross-Entropy

In large-vocabulary language models, the output projection matrix $W \in \mathbb{R}^{V \times D}$ and resulting logit tensor $H W^T \in \mathbb{R}^{B \times T \times V}$ dominate GPU VRAM.

ImplementationFwd PeakFwd + Bwd PeakHeadline Ratio
Ordinary (Snippet in Brief)1.647 GB~3.292 GB (copy + logits)1.00× (Baseline)
Ordinary Pre-Sliced1.645 GB~1.645 GB (no extra copy)2.00×
Chunked (C=1024, Checkpointed)0.206 GB~0.206 GB> 15.0× reduction
Why Checkpointing is Mandatory: Naive chunking without recomputation keeps the logits of every chunk in memory for backprop, yielding almost zero VRAM reduction. Using torch.utils.checkpoint recomputes the projection chunk during backward, freeing chunk logits immediately!
